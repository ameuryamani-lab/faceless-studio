# Lessons — dated rules from the owner's corrections and post-mortems

Read before writing (copywriter and storyboard_artist read it each run through `read_brand_file "lessons.md"`; the subject pickers should too). A rule here overrides every other brand file and the concept rules.
Appended by `append_lesson` (postmortem_writer, chief_of_staff), applied at once (no validation). Each line is tagged with the concept it was learned on (`[concept:<id> <scope>]`; `[studio]` = any concept) and carries a French wording (`rule_fr`, shown to the owner on the vitrine and logged in `data/decisions.jsonl`). The tool appends at the END of the file and skips a rule already written; the headings below are for reading, not for the tool.

<!-- Format adapted from AttentionOS (MIT, Evan Baker, commit 89f6781). -->

## Format (written by the tool)
```
- **YYYY-MM-DD** [concept:<id> <scope>] <one clear, testable rule in the imperative>
  - Evidence: <what happened: video id, numbers>
  - Source: <who or what> · by <agent>
  - FR: <the same rule in French, for the owner>
```

- Keep the owner's meaning; do not widen it.
- If a new rule contradicts an old one, the old line is kept and marked `REPLACED YYYY-MM-DD by: <new rule>`, never deleted.
- No names of real private people, no handles of other creators.
- When the same kind of rule appears three times, move it into `brand/studio.md` (any concept), `concept/<id>/rules.md` (that concept), `voice.md` or `house-style.md`.
